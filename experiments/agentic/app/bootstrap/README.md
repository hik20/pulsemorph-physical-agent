## Public-wheel recipe — executed later on this host

On a new compatible Windows/Python 3.11 host, create a new standard venv. Download the exact direct wheel URLs in `requirements-win-cp311-public.lock` with hashes, no dependencies or source builds. This recipe includes all 30 declared active runtime distributions, including the four otherwise missing packages. The wheel pins were originally resolved from public index metadata and subsequently verified against the downloaded artifacts in the separate public-wheel run. They do not assert where the earlier copied installed packages originally came from.

```powershell
python -I -m venv C:/NEW_ENV
& C:/NEW_ENV/Scripts/python.exe -I -m pip --isolated download --no-deps `
  --only-binary=:all: --require-hashes --dest C:/NEW_WHEELHOUSE `
  -r experiments/agentic/app/bootstrap/requirements-win-cp311-public.lock
& C:/NEW_ENV/Scripts/python.exe -I -m pip --isolated install --no-index `
  --find-links C:/NEW_WHEELHOUSE --no-deps --require-hashes `
  -r experiments/agentic/app/bootstrap/requirements-win-cp311-public.lock
```

The lock uses direct public URLs. For a strictly offline install, replace each URL with its locally verified wheel path while preserving every SHA256; a direct URL requirement may still be fetched even with `--no-index` if its cache is absent. The public-wheel run below used an equivalent strict local-wheel-path lock after downloading and verifying every exact artifact; it did not use a private index or a source build. Existing CPython/Windows prerequisites and separate Node, Codex CLI authentication, FFmpeg, robot/model/motion assets are not installed by this Python recipe.

## Primary documentation

- [CPython 3.11 venv](https://docs.python.org/3.11/library/venv.html): isolated package directories; environments should be recreated rather than moved.
- [CPython isolated mode](https://docs.python.org/3.11/using/cmdline.html#cmdoption-I): excludes user site/current directory and ignores Python environment variables.
- [pip hash checking](https://pip.pypa.io/en/stable/topics/secure-installs/): pinned requirements, hashes and wheel-only acquisition.

## Explicit product runtime selection

The default remains `.venv-motor`. To opt into the verified isolated interpreter for both the server process and its physical workers:

```powershell
$selectedPython = 'C:/Users/halke/.cache/pulsemorph-agentic/envs/app-cpu-py311-v1/Scripts/python.exe'
& $selectedPython -I experiments/agentic/app/preflight.py --runtime-python $selectedPython --json
& ./experiments/agentic/app/start.ps1 -RuntimePython $selectedPython -Port 8765
```

`--runtime-python` is a local CLI configuration choice, not an HTTP-supplied executable. `make_runtime` probes the selected local executable using isolated and normal startup, with Python home/path variables scrubbed and an empty temporary working directory. It requires Python 3.11, an actual venv with system site disabled, disabled user site in both modes, and matching executable identities. Preflight must itself run under the selected interpreter: passing the flag while running the old interpreter fails a critical check rather than misrepresenting the dependency probe origins. No language model, physics or authentication call is involved in this validation.


The integrated selection validation is recorded in `runtime_configuration_v1.json`. Actual selected preflight passed; deliberately running preflight with `.venv-motor` while expecting the selected C-drive interpreter failed the critical `preflight_uses_runtime_python` check, as intended. After configuration integration, `imports_v3_all_app_frozen.json` records **all 87 app unittest tests passing under `-I`**, including runtime configuration and WAV upload tests, with application source hashes unchanged through the test run. This broader proof supersedes the earlier 40-test subset for coverage; earlier receipts remain intact.
